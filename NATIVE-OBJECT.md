# ZERO — Objet natif machine

Un objet ZERO n'est pas une classe, une structure logicielle conventionnelle ou une représentation d'interface.

C'est une unité sémantique directement manipulable par la machine et le langage.

## Noyau minimal

Tout objet possède, au minimum :

EXISTENCE
IDENTITÉ
SENS
ÉTAT
RELATIONS
CAPACITÉS
OBSERVATIONS
ÉVÉNEMENTS
INCERTITUDE

La représentation physique peut changer sans changer l'identité sémantique.

## Identité != emplacement

Une adresse, une position mémoire, une surface GPU ou un emplacement physique n'est pas l'identité de l'objet.

Donc :

IDENTITÉ != ADRESSE
IDENTITÉ != POSITION
IDENTITÉ != PROJECTION
IDENTITÉ != MODALITÉ

Un objet peut être déplacé, projeté différemment, découvert progressivement ou changer d'état sans devenir un autre objet.

## Sens avant représentation

Le langage manipule le sens avant sa projection.

Exemple :

PHOTO
-> scène
-> objets observés
-> relations spatiales
-> texte détecté
-> incertitudes
-> actions possibles
-> projection visuelle / vocale / braille / autre

L'image brute peut rester disponible, mais elle n'est pas la seule représentation.

Même principe pour :

- graphique ;
- tableau ;
- vidéo ;
- document ;
- carte ;
- jeu ;
- formulaire ;
- page web ;
- CAPTCHA ;
- interface distante ;
- périphérique matériel.

## Objet incomplet

Un objet n'a pas besoin d'être entièrement compris pour exister.

Un objet inconnu peut commencer par :

EXISTENCE
-> IDENTITÉ ?
-> FRONTIÈRE
-> OBSERVATIONS
-> RELATIONS
-> CAPACITÉS
-> STRUCTURE PARTIELLE
-> SENS PARTIEL
-> INCERTITUDE

La connaissance peut augmenter sans remplacer l'identité.

## Actions

Une action est demandée sur l'objet sémantique, pas directement sur une représentation visuelle.

Exemples :

INSPECT(O)
NAVIGATE(O)
ACTIVATE(O)
EDIT(O)
SELECT(O)
INTERRUPT(O)

La projection clavier, parole, braille, souris ou tactile transforme ensuite l'interaction physique en cette même intention.

## Résultat

Toute action produit un résultat sémantique :

SUCCESS
FAILURE
DENIED
INTERRUPTED
UNKNOWN
PARTIAL

Le résultat doit rester observable et navigable.

## Accessibilité par construction

Il n'existe pas :

OBJET
+
COUCHE ACCESSIBILITÉ

Il existe :

OBJET ACCESSIBLE PAR CONSTRUCTION

L'accessibilité est donc une propriété du noyau de l'objet, comme son identité ou son état.

## Machine comme objet

Le CPU, la mémoire, le GPU, le moniteur, le clavier, l'audio, le stockage, le réseau et le firmware peuvent eux-mêmes être représentés par le même noyau.

Le modèle n'a donc pas deux mondes séparés :

HARDWARE
et
INTERFACE

Il possède un même espace sémantique avec des niveaux de capacité différents.
